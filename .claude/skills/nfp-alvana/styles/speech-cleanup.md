# Speech Cleanup (حذف تپق، تکرار و سکوت از ضبط طولانی ← سکانس پریمیر)
**وضعیت:** ✅ ابزار (کامپوزیشن ندارد) · `src/styles/speech-cleanup/pipeline/` · Node + ffmpeg + ElevenLabs Scribe · خروجی: Final Cut Pro 7 XML
- ترتیب دقیق دستورها: `pipeline/README.md` · قالب‌ها: `pipeline/config.example.json`، `pipeline/edits.example.json`

**مرجع:** یک کلاس ضبط‌شده‌ی ۷۰ دقیقه‌ای (دوربین 4K + اسکرین‌رکورد) ← ۴۲:۳۸ در پریمیر، ۳۱۶ تکه، ۱۴۴ مارکر · کانتکت‌شیت `styles/previews/speech-cleanup.jpg` (نمودار)
**اسم‌های صدازدن:** «تپق‌ها رو بگیر»، «سکوت‌ها رو کات کن»، «تکرارها رو حذف کن»، «ادیت کلاس»، «XML پریمیر»

## کی بزنیمش
- **یوتیوب بلند** (کلاس، دوره، وبینار، پادکست تصویری، ۱۰ تا ۹۰ دقیقه) — و هر ضبط گفتاری که قبل از ادیت باید تمیز شود (بعد می‌شود بخش‌هایی از آن را ریلز یا شورتز کرد).
- ورودی: فایل دوربین (و اگر هست اسکرین‌رکورد هم‌زمان)، کلید ElevenLabs، و پریمیر روی سیستم کاربر برای باز کردن XML. اگر پروژه‌ی پریمیر هست، اعداد (جای کلیپ‌ها، scale، offset اسکرین) از خود آن خوانده می‌شود.
- کار: جمله‌ی چندباره گفته‌شده ← فقط آخرین نسخه‌ی درست؛ کلمه‌ی نیمه‌کاره و شروع غلط؛ «اِمم»، سرفه، آب خوردن؛ «که که»؛ مکث‌های بلند؛ بخشی که کاربر می‌گوید حذف شود؛ مارکر برای blur و چک.
- **کی نه:**
  - ویدیوی کوتاه رو به دوربین که صفحه یا المان روی آن می‌خواهد ← `talk-page` یا `talk-cutout` (مکث‌های بین جمله را آنجا با یک برش ساده کم کن).
  - نریشن TTS ← `tools/vo-tighten.mjs` (فقط مکث بین جمله‌ها).
  - کاربر پریمیر ندارد و فقط یک MP4 می‌خواهد ← همان `segments-A.json` را با ffmpeg (trim + concat تصویر و صدا) بچسبان؛ `render-audio.mjs` الگوی صدا را دارد.

## ظاهر (خروجی)
- یک **سکانس تازه** در همان پروژه (File › Import): V1 دوربین با همان Motion سکانس اصلی، V2 اسکرین‌رکورد هم‌زمان (اختیاری)، A1 صدا به‌صورت WAV مونو (روی هر دو کانال پخش می‌شود). سکانس اصلی دست نمی‌خورد.
- **مارکرها:** روی هر کات بررسی‌شده (تکرار، تپق، بخش حذفی…) با یادداشت و «حذف شد: …»؛ مارکرهای جدا برای `blur` و `check` روی همان لحظه‌ی تایم‌لاین تازه.
- لبه‌ها روی فریم سکانس (fps سکانس) و داخل سکوت واقعی؛ تکه‌های کوتاه‌تر از ۹ فریم با کات کناری یکی می‌شوند.

## شروع سریع
1. **صدا:** کانالی که صدای گوینده دارد (گاهی فقط چپ) ← `voice16.flac` (متن) + `voice-mono.wav` (ترک A1) ← `node …/envelope.cjs` (پوش ۱۰ms). اسکرین هست؟ `bash …/screen-activity.sh`.
2. **متن:** `node --env-file=.env …/stt-chunks.mjs $D/voice16.flac $D/stt fas` ← `stt-patch` روی اتصال تکه‌هایی که وسط گفتار افتاده‌اند ← `fix-timing`.
3. **کات خودکار:** `node …/analyze.mjs $D/stt/words.json $D/env10ms.f32 $D/cuts-auto.json 60`.
4. **خواندن:** `node …/dump-transcript.mjs` ← `utterances.txt` را **کامل** بخوان، `review.mjs` را ببین، و `edits.json` را بنویس (تکرارها، شروع‌های غلط، بخش حذفی، مارکرها).
5. **ساخت:** `cp …/config.example.json $D/xml-config.json` (پر کن) ← `node …/build-cuts.mjs $D A` ← `node …/make-xml.mjs $D/xml-config.json $D/cuts-A.json $D/class-cut.xml $D/segments-A.json`.
6. **چک:** `render-audio` ← `joins` (همه‌ی اتصال‌ها را بخوان) ← Scribe دوباره روی صدای ادیت‌شده ← `compare-stt` ← `diag` / `stt-window` برای جاهای مشکوک ← اصلاح `edits.json` و از قدم ۵ دوباره.
7. **پریمیر:** File › Import ← XML. به کاربر بگو سکانس تازه را ببیند؛ سؤال‌های باز (بخش‌های مشکوک، blurها) را با شماره‌ی مارکر بپرس.

## API (ورودی و خروجی هر ابزار)
| ابزار | ورودی ← خروجی |
|---|---|
| `envelope.cjs` | صدا ← `env10ms.f32` (dBFS هر ۱۰ms) |
| `stt-chunks.mjs` | صدا، پوشه، `lang`، دقیقه‌ی تکه ← `stt/words.json`، `chunks.json`، `transcript.txt` |
| `fix-timing.mjs` | `stt/`، پوش ← `words.json` اصلاح‌شده (اصل در `words-raw.json`) |
| `analyze.mjs` | کلمه‌ها، پوش، fps ← `cuts-auto.json` (pause، filler، stumble، repeat، retake؛ `sure` یعنی خودکار اعمال شود) |
| `dump-transcript.mjs` | کلمه‌ها ← `utterances.txt` (U1، U2… با زمان) + `utterances.json` |
| `build-cuts.mjs` | پوشه، نسخه (A/B) ← `cuts-A.json` |
| `make-xml.mjs` | config، cuts ← XML + `segments-A.json` |
| `render-audio.mjs` | segments، صدا ← صدای ادیت‌شده |
| `joins.mjs` · `compare-stt.mjs` · `diag.mjs` | ← `joins-A.txt`، گزارش جاافتاده/اضافه کنار اتصال‌ها، `diag/item-NN.txt` |

## دستورهای کار (قانون‌های برش)
- **تکرار:** جمله‌ای که چند بار پشت هم گفته شده ← فقط **آخرین نسخه‌ی درست**. اگر آخری نامفهوم است، نسخه‌ی قبلیِ واضح.
- **مکث اتصال:** ۰.۴۵ث بعد از آخر جمله یا سؤال، ۰.۳ بعد از ویرگول، ۰.۱۵ وسط جمله؛ فقط از سکوت خود کات.
- **لبه:** روی دره‌ی بلندی؛ پرکننده‌ی چسبیده بدون دره کات نمی‌شود؛ شروع نرم کلمه (س، ش، ه) کامل می‌ماند.
- **سکوت مفید:** پخش ویدیو و اسکرول روی صفحه ← مکث می‌ماند؛ سکوت بلند کار روی صفحه ← ثانیه‌ی آخرش می‌ماند؛ سکوت بعد از آخرین کلمه ← تا ۱ ثانیه.
- **دستور داخل ضبط، تماس، رمز تایپ‌شده:** بپرس، خودسر اجرا نکن ← مارکر.

## صدا
- صدای A1 همان صدای گوینده است، بدون پردازش. اگر صدا فقط روی یک کانال است، همان کانال را مونو کن (وگرنه یک گوش خالی است).
- چک کیفیت با گوش: `render-audio.mjs` صدای ادیت‌شده را دقیقاً مثل تایم‌لاین می‌سازد (کات سخت).

## درس‌ها
- ⚠ Scribe: کلمه‌ی نیمه‌کاره `--`، نفس و سرفه `[…]`؛ بعضی پرکننده‌ها را فقط چک دوم می‌شنود؛ گاهی یک کلمه را ۴۶ ثانیه کش می‌دهد یا کلمه‌ی صفرثانیه‌ای جای غلط می‌دهد (`fix-timing`)؛ متن فایل بلند گاهی جمله‌ای را جا می‌اندازد — آن تکه را تنها بفرست (`stt-window`، WAV نه FLAC؛ FLAC بعد از seek بلوک اول کوچک دارد و انکودر خطا می‌دهد).
- ⚠ صوت «س» کم‌انرژی است و شبیه دره دیده می‌شود؛ لبه «سه» را برید ← `endAt`/`startAt` دستی.
- ⚠ حذف تکرار وقتی فاصله‌ی قبلش کوتاه بود جمله‌ها را به هم چسباند ← قانون مکث اتصال (بالا).
- ⚠ fps در XML = fps **سکانس** (مثلاً ۶۰)، نه فایل دوربین (۲۵). اسکیل غیریکنواخت = Basic Motion scale + Distort aspect؛ مونو = `premiereTrackType="Mono"`.
- **هزینه:** حدود ۲۰ کرید در دقیقه؛ کار کامل ۷۰ دقیقه‌ای با دو دور چک ≈ ۳۲۵۰ کرید. قبل از شروع اعتبار حساب را بپرس.
- **زمان:** متن اول ~۱۰ دقیقه برای ۷۰ دقیقه صدا (دو تکه هم‌زمان)؛ خواندن و نوشتن `edits.json` بیشترین زمان کار است.

## اجرا و تحویل
- همه CPU و شبکه؛ کارت گرافیک لازم نیست. روی ابر هم اجرا می‌شود ولی پریمیر باید روی سیستم کاربر باشد (فقط XML تحویل می‌شود).
- تحویل: `class-cut.xml` + `cuts-A.json` (برای اصلاح بعدی) + فهرست مارکرها و سؤال‌های باز برای کاربر. فایل‌های دوربین و صدا جابه‌جا نشوند (مسیرهای مطلق داخل XML).
